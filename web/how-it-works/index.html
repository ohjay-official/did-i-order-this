How it works

The AI reads the claim. Code checks the ledger

A delivery email can look official and still be a lure. This product splits the work on purpose: a model reads messy wording, and deterministic code decides the verdict.

01

Keep a ledger on this device

The sample inbox starts with a small demo ledger. You can also import an Amazon order-history CSV or ZIP, a PayPal activity CSV, or a generic CSV with common columns. The file is parsed in the browser and is not uploaded.

02

Open the email you want to check

On the hosted site, pick a sample thread. In the Chrome extension, the side panel reads the open Gmail thread as text only. There is no Gmail API access and no mailbox scan.

03

Try on-device AI first

A check starts in on-device mode. The model returns a structured claim: who the email claims to be, what it wants you to do, and which number it cites. If on-device AI is not available, the site asks before sending the email to the cloud. If you refuse, you can run a limited check with no AI.

04

Code issues the verdict

The model does not decide Safe, Warning, or Neutral. Code matches the claim to your ledger. For a carrier email, a matching tracking number is Safe and a miss is Warning. If you have no expected parcels, the headline is exactly: You're not expecting any parcel right now.

Every verdict shows a source label: Checked on this device, Checked in the cloud, Limited check (no AI), or Check not completed.
