Privacy and security

On-device first, and honest about the cloud

The product exists so a delivery email can be checked without sending your inbox to a server. Here is exactly what stays here, and what can leave.

What stays on this device

Your ledger lives in this browser or in the extension's local storage. Imported CSV and ZIP files are read locally and are not uploaded. The Chrome extension's content script sends only the open thread's text to the side panel, over extension messaging. It does not use the Gmail API or the gmail.readonly scope. It does not scan the rest of the mailbox.

How a check starts

A check starts in on-device mode through Firebase AI Logic. The hosted site and the extension both use that path. Product code does not call the browser Prompt API directly.

When something can go to the cloud

If on-device AI is not available on the hosted site, you see a consent dialog: Check this email in the cloud, or Do not send. The email is sent off the device only if you agree. If you refuse, you can run a limited check that uses no AI. The extension never sends mail to the cloud. If you want a cloud check, you open the hosted site and agree there.

App Check

Cloud AI calls from the production site go through Firebase App Check with reCAPTCHA Enterprise, registered for did-i-order-this.vercel.app. App Check debug tokens are not shipped in the production client. Preview deployments do not use the production reCAPTCHA key.

What the cloud model sees, if you agree

If you consent to a cloud check, the text of that one email is sent to generate the structured claim. Official-domain and lure-template packs used in the verdict are public reference data compiled into the app, not your private mail.

What this product does not do

  • It does not read SMS, WhatsApp, or other phone messages.
  • It does not ask for a Gmail login on the hosted site.
  • It does not sell a list of your orders.
