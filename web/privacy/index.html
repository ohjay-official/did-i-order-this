Privacy and security

What stays here. What can leave.

The product exists so a delivery email can be checked without sending your inbox to a server. Here is exactly what stays on this device, and what can leave.

Stays on this device

  • Your orders, shipments, and known senders, in this browser or in the extension's local storage
  • Imported CSV and ZIP files, which are read locally and are not uploaded
  • The open Gmail thread, read as text only by the extension, with no Gmail API access and no mailbox scan
  • On-device inference through Firebase AI Logic, which is how every check starts

Leaves only if you agree

  • The text of that one email, and only on the hosted site, after a consent dialog
  • Nothing, if you choose Do not send. You can still run a limited check with no AI
  • Nothing from the Chrome extension, which never sends mail to the cloud
  • App Check with reCAPTCHA Enterprise protects production cloud calls on did-i-order-this.vercel.app

How a check starts

A check starts in on-device mode through Firebase AI Logic. The hosted site and the extension both use that path. Product code does not call the browser Prompt API directly.

What the cloud model sees, if you agree

If you consent to a cloud check, the text of that one email is sent to generate the structured claim. Official-domain and lure-template packs used in the verdict are public reference data compiled into the app, not your private mail. App Check debug tokens are not shipped in the production client. Preview deployments do not use the production reCAPTCHA key.

What this product does not do

  • It does not read SMS, WhatsApp, or other phone messages.
  • It does not ask for a Gmail login on the hosted site.
  • It does not sell a list of your orders.
